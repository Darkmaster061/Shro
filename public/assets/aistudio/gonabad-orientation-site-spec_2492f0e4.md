## ۱. نقش و قوانین کلی (برای Gemini)

تو یک تیم کامل شامل طراح UI/UX ارشد، توسعه‌دهنده فول‌استک، متخصص امنیت و متخصص عملکرد (performance) هستی. خروجی باید در حد یک محصول واقعی و حرفه‌ای باشد، نه یک دموی ساده.

قوانین غیرقابل‌مذاکره:

1. **فارسی و راست‌به‌چپ (RTL) کامل.** همه متن‌ها، چیدمان، آیکون‌های جهت‌دار، انیمیشن‌ها و فرم‌ها باید برای RTL درست کار کنند. ارقام فارسی، تقویم شمسی (جلالی) در همه‌جا.
2. **هیچ وابستگی به سرویس‌های خارجی ممنوع است.** سایت نهایی روی سرور ایرانی و گاهی روی شبکه ملی اطلاعات اجرا می‌شود. پس:
   - فونت‌ها (وزیرمتن یا ایران‌سنس) باید به‌صورت فایل محلی (woff2) داخل پروژه باشند، نه Google Fonts.
   - هیچ CDN (مثل cdn.jsdelivr، unpkg، esm.sh، cdnjs، Tailwind CDN) نباید در خروجی نهایی باشد. همه پکیج‌ها با npm نصب و bundle شوند.
   - هیچ فراخوانی به Google Analytics، Google Maps، reCAPTCHA، Firebase، Gemini API، OpenAI یا هر API خارجی ممنوع است.
   - نقشه‌ها: از تصویر SVG/PNG محلی یا Leaflet با تایل‌های آفلاین/تصویر سفارشی استفاده کن، نه Google Maps. لینک «مسیریابی» به نشان/بلد/neshan باز شود.
3. **امنیت از ابتدا** (بخش ۱۰). داده شخصی کمینه جمع‌آوری شود.
4. **کد تمیز و ماژولار** با TypeScript، کامنت فارسی کوتاه در جاهای مهم، و یک لایه `api` جدا (بخش ۹) تا بشود بک‌اند را بعداً جایگزین داده‌های نمونه کرد.
5. **عملکرد روی گوشی ضعیف** و اینترنت کند: صفحه اول زیر ۳ ثانیه روی 4G معمولی. جلوه‌های سنگین باید با تشخیص دستگاه و `prefers-reduced-motion` خودکار ساده شوند.
6. **محتوای ساختگی ممنوع.** برای متن و آمار واقعی از placeholder با برچسب `[نیاز به تکمیل]` استفاده کن. فقط متن‌های عمومی و راهنما را می‌توانی بنویسی.
7. لحن کل سایت: محترمانه، گرم، صمیمی و دانشجویی. نه خشک اداری و نه شعاری و پر از اغراق.
8. در پایان هر فاز: فهرست فایل‌ها، دستور اجرا، و فهرست کارهایی که من باید دستی انجام بدهم را بنویس.

## ۲. معرفی پروژه و مخاطب

- **هدف:** دانشجوی نوورود در روزهای ثبت‌نام و هفته اول دانشگاه (حدود ۳۰۰ نفر) بدون سردرگمی همه‌چیز را در یک‌جا پیدا کند: مراحل ثبت‌نام، خوابگاه، سوالات متداول، معرفی بسیج و هیئت، و دریافت ژتون صبحانه.
- **مخاطب اصلی:** نوورودها و خانواده‌هایشان، عمدتاً با گوشی موبایل (طراحی mobile-first).
- **مخاطب دوم:** مسئولان بسیج و هیئت (ادمین)، مسئولان پخش صبحانه (اسکنر ژتون).
- **بازه اوج بار:** سه روز ثبت‌نام. حدود ۳۰۰ کاربر که ممکن است همزمان ۵۰ تا ۱۰۰ نفر باشند.

## ۳. معماری فنی پیشنهادی

| لایه | انتخاب |
|---|---|
| Frontend | React + TypeScript + Vite |
| استایل | Tailwind CSS (نصب محلی، نه CDN) + CSS variables برای تم |
| انیمیشن | Framer Motion (یا Motion One) برای رابط؛ Three.js/ogl فقط برای صحنه hero و با lazy-load |
| مسیریابی | React Router |
| ابزار فرم | React Hook Form + Zod |
| تقویم شمسی | `jalaali-js` یا `dayjs` + پلاگین jalali (محلی) |
| اسکن QR | `qr-scanner` یا `html5-qrcode` (محلی) |
| ساخت QR | `qrcode` (محلی) |
| نمایش PDF | `pdfjs-dist` با worker محلی |
| Backend (فاز ۲) | Node.js + Express (یا Fastify) + SQLite (`better-sqlite3`) |
| احراز هویت ادمین | session کوکی HttpOnly + argon2/bcrypt |
| استقرار | Docker (یک کانتینر)، سازگار با Liara/Hamravesh و VPS معمولی |

اصول: سایت **PWA قابل نصب** باشد (آفلاین برای صفحات اطلاعات و اسکنر ژتون با صف همگام‌سازی).

## ۴. هویت بصری و طراحی (جلوه‌های Wow)

### ۴.۱ سیستم طراحی
- **حال‌وهوا:** مدرن، سینمایی، معنوی و دانشجویی. پس‌زمینه تیره (سبز زمردی خیلی تیره / نفتی) با رنگ تأکید طلایی/کهربایی و سفید گرم. یک تم روشن هم بساز و دکمه تغییر تم بگذار.
- **رنگ‌ها به‌صورت CSS variable** تعریف شوند تا بعداً از پنل ادمین یا یک فایل قابل تغییر باشند.
- **تایپوگرافی:** وزیرمتن (یا ایران‌سنس) محلی. تیترهای درشت، فاصله خطوط راحت برای فارسی، حداقل اندازه متن بدنه ۱۶px.
- **لوگوها:** دو جایگاه مجزا برای لوگوی بسیج و لوگوی هیئت. آپلود از پنل ادمین (PNG/SVG/WebP). تا زمان آپلود، یک placeholder زیبا نمایش بده. لوگو در header، hero، footer، favicon و تصویر اشتراک‌گذاری (OG image) استفاده شود.
- **گوشه‌ها و سایه:** کارت‌های شیشه‌ای (glassmorphism ملایم)، گوشه‌های گرد ۱۶ تا ۲۴px، سایه نرم، بوردر گرادیانی ظریف.

### ۴.۲ جلوه‌های بصری و تعاملی (حتماً پیاده‌سازی شود)
1. **Hero سینمایی:** پس‌زمینه ذرات نورانی/شفق (aurora) با WebGL یا Canvas که به حرکت موس/ژیروسکوپ گوشی واکنش می‌دهد. روی دستگاه ضعیف یا reduced-motion به یک گرادیان متحرک ساده تبدیل شود.
2. **ورود سینمایی (Intro):** انیمیشن کوتاه ۲ تا ۳ ثانیه‌ای ظاهر شدن لوگوها و عنوان، با دکمه «رد کردن».
3. **اسکرول روایی (scroll-storytelling):** بخش‌ها هنگام اسکرول با parallax، reveal و عدد شمارنده (counter) ظاهر شوند.
4. **کارت‌های سه‌بعدی (tilt)** برای کانون‌ها و خوابگاه‌ها، با افکت نور دنبال‌کننده نشانگر.
5. **دکمه‌های مغناطیسی** و ریپل نرم هنگام کلیک.
6. **انتقال بین صفحات** روان (page transitions) بدون پرش.
7. **میکروتعامل‌ها:** hover، فوکوس، اسکلتون لودینگ، toast، تیک انیمیشنی هنگام تکمیل چک‌لیست.
8. **گالری تصاویر** با lightbox، swipe و زوم؛ تصاویر lazy-load و در چند اندازه (srcset).
9. **تایم‌لاین تعاملی** برای برنامه روزهای ثبت‌نام و تاریخچه بسیج.
10. **تغییر تم تاریک/روشن** با ذخیره انتخاب.
11. **صدا:** هیچ صدای خودکار نباشد.
12. **دسترس‌پذیری:** کنتراست مناسب، ناوبری با کیبورد، `aria-label` فارسی، احترام به `prefers-reduced-motion`.

> قانون طلایی: زیبایی نباید سرعت را بکشد. بودجه عملکرد: JS اولیه کمتر از ۲۵۰KB gzip، تصاویر WebP/AVIF، صحنه سه‌بعدی lazy.

## ۵. نقشه سایت و صفحات

### ۵.۱ صفحه خوش‌آمد (Gate اولیه)
- هنگام اولین ورود، یک **مودال تمام‌صفحه** با عنوان «به خانواده دانشجویی خوش آمدی» نمایش بده.
- دو کارت بزرگ: **کانال بسیج** و **کانال هیئت** با دکمه «عضویت» (لینک تلگرام). کنار هر کدام لینک جایگزین ایتا/بله/روبیکا هم باشد (قابل تنظیم از ادمین).
- دکمه «عضو شدم، ادامه» فقط پس از کلیک روی هر دو لینک و یک تأخیر کوتاه (۵ ثانیه) فعال شود. وضعیت در `localStorage` ذخیره شود تا دوباره نمایش داده نشود.
- **توجه فنی:** سایت نمی‌تواند عضویت واقعی در تلگرام را تأیید کند (سرورهای ایرانی معمولاً به API تلگرام دسترسی ندارند). پس این Gate از نوع «سوفت‌گیت» است. صادقانه بنویس: «لطفاً عضو شو تا اطلاعیه‌ها از دستت نرود.» تأیید عضویت واقعی با ربات بله/ایتا در فاز اختیاری ۵ بررسی شود.

### ۵.۲ صفحه اصلی
Hero، شمارنده روز تا شروع کلاس‌ها/روز ثبت‌نام، دسترسی سریع به ۶ بخش اصلی (آیکون بزرگ)، آخرین اطلاعیه‌ها، چک‌لیست پیشرفت نوورود، دکمه شناور «سوالی داری؟».

### ۵.۳ راهنمای نوورود
- **چک‌لیست تعاملی ثبت‌نام** (مرحله‌ها قابل تیک‌زدن، درصد پیشرفت، ذخیره محلی). مراحل پیش‌فرض را بر اساس یک ثبت‌نام عمومی پیشنهاد بده ولی مشخص کن `[نیاز به تکمیل و تطبیق با فرایند واقعی دانشگاه]`.
- **تایم‌لاین روزهای ثبت‌نام** با ساعت و محل `[نیاز به تکمیل]`.
- **مدارک لازم** به‌صورت کارت‌های تیک‌خور.
- **مشکلات رایج و راه‌حل** (آکاردئون).
- **سوالات متداول (FAQ):** جستجوی آنی و تحمل غلط املایی فارسی (fuzzy search محلی، نرمال‌سازی ی/ي، ک/ك، نیم‌فاصله، ارقام). دسته‌بندی، فیلتر، رأی «مفید بود/نبود». مدیریت از ادمین.
- **«سوالت را بپرس»:** فرم ناشناس یا نام‌دار که پاسخ ادمین بعداً به FAQ اضافه شود.
- **بدون ربات هوشمند خارجی.** جستجوی داخلی FAQ کافی است.

### ۵.۴ خوابگاه‌ها
- فهرست خوابگاه‌ها به‌صورت کارت (دختران/پسران، متأهلی در صورت وجود).
- صفحه هر خوابگاه: گالری عکس، آدرس، نقشه/مسیر، هزینه، ظرفیت، امکانات، قوانین، ساعت ورود و خروج، شماره مسئول، مدارک لازم، و سوالات متداول خوابگاه.
- **ابزار مقایسه** خوابگاه‌ها (جدول کنار هم).
- همه داده‌ها از پنل ادمین. تا ورود داده واقعی: `[نیاز به تکمیل]`.

### ۵.۵ بسیج دانشجویی
- معرفی بسیج دانشجویی دانشگاه با تصاویر حرفه‌ای، تایم‌لاین، آمار (counter)، برنامه‌ها و رویدادها، گالری، قسمت «چطور عضو شوم؟».
- **معرفی کانون‌ها:** کارت‌های سه‌بعدی؛ هر کانون صفحه‌ای دارد با توضیح، مسئول، برنامه‌ها، عکس، لینک عضویت و ارتباط.
- **فایل PDF حدود ۱۰۰ صفحه‌ای (معرفی کانون‌ها):** نمایشگر داخلی با `pdfjs-dist`: بارگذاری تنبلانه صفحات، تصاویر بندانگشتی، جستجو در متن، پرش به صفحه، حالت تمام‌صفحه، دکمه دانلود. فایل را از ادمین آپلود کن (تا ۵۰MB). اگر نمایشگر روی دستگاهی کار نکرد، لینک دانلود مستقیم بگذار.
- محتوا باید بدون لحن شعاری و با نگاه خدماتی/فرهنگی برای نوورودها نوشته شود.

### ۵.۶ هیئت
- معرفی هیئت، برنامه‌ها (تقویم شمسی با فیلتر)، مراسم‌ها، گالری، اخبار، و فرم همکاری/عضویت.
- **بخش «ژتون صبحانه»** (سیستم کامل در بخش ۶).

### ۵.۷ اطلاعیه‌ها و رویدادها
تقویم شمسی، فهرست، فیلتر، افزودن به تقویم (فایل ICS)، اعلان داخل سایت.

### ۵.۸ تماس با ما و فوتر
- فوتر: شماره‌های تماس، آدرس‌های اجتماعی (تلگرام، ایتا، بله، روبیکا، اینستاگرام اختیاری)، ساعت پاسخگویی، لینک‌های سریع. همه قابل ویرایش از ادمین.
- صفحه «تماس با ما» شامل فرم پیام، شماره‌ها (کلیک برای تماس)، و موقعیت دفتر بسیج و هیئت.

## ۶. سیستم ژتون صبحانه (جزئیات کامل)

هدف: فقط نوورودهای ثبت‌شده صبحانه بگیرند و هر نفر در هر وعده فقط یک بار.

### ۶.۱ مدل داده
```
students(id, first_name, last_name, first_name_norm, last_name_norm,
         birth_hash, coupon_code, note, active, created_at)
meals(id, name, date_jalali, start_time, end_time, active)
claims(id, student_id, meal_id, claimed_at, staff_user_id, UNIQUE(student_id, meal_id))
audit_log(id, user_id, action, detail, ip, created_at)
```
- `birth_hash` = HMAC-SHA256(pepper_محرمانه, نرمال‌شده(نام|نام‌خانوادگی|تاریخ تولد)). تاریخ تولد خام ذخیره نشود. هدف: اگر دیتابیس لو برود، تاریخ تولد افراد افشا نشود.
- `coupon_code` رشته تصادفی ۱۲۸ بیتی (غیرقابل حدس).
- نرمال‌سازی نام: تبدیل ی/ي، ک/ك، حذف نیم‌فاصله و فاصله‌های اضافه، تبدیل ارقام، حروف کوچک.

### ۶.۲ ورود لیست (ادمین)
- آپلود فایل CSV/Excel با ستون‌های: نام، نام‌خانوادگی، تاریخ تولد شمسی (۱۳۸۸/۰۵/۲۰).
- پیش‌نمایش، اعتبارسنجی، گزارش خطا و ردیف‌های تکراری، تأیید نهایی.
- افزودن/ویرایش/حذف دستی، غیرفعال‌سازی، جستجو.

### ۶.۳ دریافت ژتون توسط دانشجو
1. دانشجو نام، نام‌خانوادگی و تاریخ تولد (با انتخاب‌گر شمسی) را وارد می‌کند.
2. اگر مطابقت داشت، **کارت ژتون دیجیتال** با QR، نام، و دکمه «ذخیره تصویر» نمایش داده می‌شود (قابل افزودن به صفحه اصلی گوشی). QR باید بدون اینترنت هم نمایش داده شود (بعد از اولین بار کش شود).
3. پیام خطا همیشه یکسان و عمومی است («اطلاعات یافت نشد، با مسئول هیئت تماس بگیر») تا امکان حدس‌زدن لیست نباشد.
4. محدودیت تعداد تلاش (مثلاً ۵ بار در ۱۰ دقیقه برای هر IP و هر نام).
5. گزینه «چاپ کارت» برای کسانی که گوشی ندارند (ادمین فایل PDF همه کارت‌ها را بگیرد).

### ۶.۴ اسکنر مسئول پخش (PWA)
- صفحه ورود جدا برای نقش «مسئول پخش».
- دوربین گوشی QR را اسکن می‌کند و **نتیجه تمام‌صفحه و بزرگ** نشان می‌دهد:
  - سبز: «مجاز» + نام و نام‌خانوادگی (و ثبت دریافت)
  - قرمز: «قبلاً دریافت کرده» + ساعت دریافت
  - خاکستری: «نامعتبر/غیرفعال»
- با صدا/لرزش اختیاری، بدون تأخیر.
- **جستجوی دستی** با نام برای زمانی که QR کار نمی‌کند.
- **حالت آفلاین:** لیست و وضعیت دریافت‌ها روی دستگاه کش شود و دریافت‌ها در صف بماند و هنگام اتصال همگام شود. هنگام تضاد، اولین ثبت معتبر است.
- شمارنده زنده: چند نفر گرفتند، چند نفر مانده.

### ۶.۵ گزارش‌ها (ادمین)
تعداد دریافت هر وعده، لیست نگرفته‌ها، لیست افراد مشکوک (تلاش مجدد)، خروجی Excel، نمودار ساده.

## ۷. پنل ادمین

- ورود جدا در مسیر `/admin` با حساب کاربری و رمز قوی؛ **TOTP دوعاملی اختیاری**.
- **نقش‌ها:**
  - `owner`: همه‌چیز
  - `editor`: ویرایش محتوا (FAQ، اطلاعیه، خوابگاه، بسیج، هیئت)
  - `food_manager`: مدیریت لیست نوورودها و گزارش ژتون
  - `scanner`: فقط اسکنر
- **مدیریت محتوا:** FAQ، اطلاعیه‌ها، رویدادها، خوابگاه‌ها (متن، عکس، قیمت، آدرس)، کانون‌ها، گالری، PDF، لینک‌های کانال‌ها، شماره‌های تماس.
- **تنظیمات ظاهری:** آپلود لوگوی بسیج، لوگوی هیئت، favicon، تصویر hero، تغییر رنگ تأکید.
- پیش‌نمایش قبل از انتشار، پیش‌نویس/منتشرشده، تاریخچه تغییرات ساده.
- ثبت `audit_log` از هر عملیات حساس.

## ۸. ایده‌های خلاقانه اضافه (به ترتیب اولویت)

1. **چک‌لیست شخصی نوورود** با نوار پیشرفت و پیام تشویقی.
2. **نقشه تعاملی دانشگاه** (SVG): کلیک روی ساختمان‌ها؛ اطلاعات واحد ثبت‌نام، خوابگاه، سلف، نمازخانه، دفتر بسیج و هیئت.
3. **«دانشجوی راهنما»:** هر نوورود می‌تواند سوال بپرسد و پاسخ سریع از دانشجوی قدیمی‌تر بگیرد (از طریق صف ادمین).
4. **شمارنده معکوس** تا شروع کلاس، رویدادها و مراسم.
5. **لیست «چه چیزی با خودم ببرم؟»** برای خوابگاه (چک‌لیست قابل چاپ).
6. **آزمون کوتاه «کدام کانون به من می‌خورد؟»** (۶ تا ۸ سوال، پیشنهاد کانون بر اساس علاقه‌مندی).
7. **اطلاعیه فوری (Banner)** که ادمین فعالش می‌کند.
8. **نظرسنجی کوتاه** رضایت از ثبت‌نام و صبحانه (ناشناس).
9. **PWA و اعلان داخل برنامه** (بدون نیاز به سرویس خارجی).
10. **حالت کم‌حجم:** نسخه سبک سایت برای اینترنت ضعیف.
11. **صفحه چاپی** برای راهنمای ثبت‌نام (PDF خودکار).
12. **دفتر خاطرات/گالری «اولین هفته من»** با بارگذاری عکس دانشجویی (با تأیید ادمین؛ پیش‌فرض خاموش).

## ۹. معماری داده و API

در فاز ۱ همه داده‌ها از یک لایه `src/api/` خوانده شوند که فعلاً از داده نمونه (mock) استفاده می‌کند و با یک تغییر ساده می‌تواند به بک‌اند وصل شود.

**نقاط پایانی (Endpoints) پیشنهادی (فاز ۲):**


## ۱۰. امنیت (الزامی)

- **HTTPS اجباری**، هدرهای امنیتی (helmet)، **CSP سخت‌گیرانه** (بدون inline script)، HSTS.
- **محدودیت نرخ (rate limit)** روی ورود ادمین، جستجوی ژتون و فرم‌ها.
- **CAPTCHA بدون سرویس خارجی** (مثلاً proof-of-work سبک یا سوال ساده خودمیزبان) روی فرم‌های عمومی. فیلد honeypot هم اضافه شود.
- رمز ادمین با argon2/bcrypt، کوکی `HttpOnly; Secure; SameSite=Strict`، محافظت CSRF، انقضای نشست، قفل موقت پس از چند تلاش ناموفق.
- **آپلود امن:** بررسی نوع واقعی فایل (magic bytes)، محدودیت حجم، تغییر نام تصادفی، بازپردازش تصاویر با sharp و حذف EXIF، عدم اجرای فایل‌های آپلودی، PDF فقط به‌صورت استاتیک.
- کوئری‌های پارامتری (جلوگیری از SQL Injection)، پاک‌سازی خروجی (جلوگیری از XSS).
- **حداقل‌سازی داده:** فقط نام، نام‌خانوادگی و هش تاریخ تولد؛ بدون کد ملی یا شماره تماس دانشجو.
- **حذف خودکار داده:** تنظیم «پاک کردن لیست نوورودها X روز پس از پایان ثبت‌نام».
- لاگ‌ها بدون اطلاعات شخصی؛ پشتیبان‌گیری روزانه رمزگذاری‌شده؛ اسرار فقط در متغیرهای محیطی (`.env`، هرگز در کد).
- `npm audit` و قفل نسخه‌ها (`package-lock`)، به‌روزرسانی وابستگی‌ها.
- مسیر `/admin` فقط با احراز هویت (پنهان بودن مسیر، امنیت محسوب نمی‌شود).

## ۱۱. عملکرد، PWA و سئو

- Code-splitting، lazy-load برای PDF viewer و صحنه سه‌بعدی، preload فونت اصلی.
- تصاویر: WebP/AVIF، `srcset`، `loading="lazy"`.
- Service Worker برای کش صفحات اطلاعات، آیکون‌ها و اسکنر؛ manifest فارسی با آیکون‌های لوگو.
- متای OG/Twitter، عنوان و توضیح فارسی، `sitemap.xml`، `robots.txt`.
- نمره Lighthouse هدف: Performance ≥ ۸۵، Accessibility ≥ ۹۵ روی موبایل.
- کش سمت سرور برای API‌های عمومی (مثلاً ۶۰ ثانیه) برای تحمل هجوم روز ثبت‌نام.
